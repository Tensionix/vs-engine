# VapourWiki — пресеты Audion VS Engine

28 пресетов Audion VS Engine в 4 палитрах: какой взять для какого материала, что каждый делает, его главные настройки и подходящий кодер. В окне (`Start.exe`) пресет — переключатель в группе своей палитры, в консоли — `vs_cli.cmd run --operation <id> --set <поле>=<значение>`.
Как работать в окне и в консоли — [USER_GUIDE_RU.md](../USER_GUIDE_RU.md); все поля с диапазонами и вариантами — [OPERATIONS_RU.md](../OPERATIONS_RU.md).

### Цепочки

Один прогон — один пресет. Цепочка — несколько прогонов подряд: результат шага ложится в `<Назначение>\<Палитра>\<пресет>_<кодер>\`, и эта папка становится Источником следующего шага. Промежуточные шаги пишите в `prores_lt`: файл со сжатием с потерями между шагами передаёт свои потери каждому следующему. Итоговый кодер — только на последнем шаге. Шаг, который повторяется часто, стоит сохранить профилем (раздел «ПРОФИЛИ»).

| Задача | Шаги |
|---|---|
| Ночной таймлапс в плёночный образ | `shadow_denoise_sota` → `filmic_rebuild` → `cinematic` |
| Архив VHS в отреставрированный мастер | `qtgmc_deinterlace` → `derainbow_decross` → `mvtools_mcdegrain` → `archive_clean` |
| Старая копия из сети в файл, пригодный для проекта | `deblock_h264_artefacts` → `dehaze_local_contrast` → `pregrade_prep` |
| NTSC DVD с телесином в мастер 24p | `tivtc_ivtc` → `archive_clean` |
| Современная цифровая съёмка в плёночный образ | `mild_denoise` → `film_35mm` |
| Архив SD или HD в мастер вдвое больше, с тонким зерном | `vsmlrt_realesrgan_2x` (без MLRT — `nnedi3_upscale_2x`) → `deband_fine_grain` |
| Мягкое HD в плёночный образ 4K | `soft_hd_rebuild_2x` → `film_35mm` |

Зерно и плёночные образы — после увеличения: зерно, положенное до него, увеличится вместе с картинкой.

## ТОЧНОСТЬ

Техническая подготовка: шумодав, дебанд, зерно. Группы идут в порядке работы: Шумодав, затем Дебанд, затем Мастер — он делает и то и другое и кладёт зерно. Зерно любого пресета начинается с постоянного начального числа: один файл даёт одни и те же кадры при каждом прогоне.

### Шумодав

#### Мягкий шумодав (`mild_denoise`)

Спектральный шумодав DFTTest на процессоре: одинаковый результат на любой машине, ни видеокарта, ни OpenCL не нужны. Первый выбор, когда о материале мало что известно: лёгкий ровный шум, небольшая чистка почти без риска.

| Поле | Значения | Что меняет |
|---|---|---|
| `strength` Сила | `light`, `medium`, `strong`; по умолчанию `medium` | Сигма DFTTest 4, 8 или 14. |
| `noise` Шум | `auto`, `fixed`; по умолчанию `auto` | Авто поднимает сигму по шуму, измеренному в исходнике, и никогда не опускает её ниже настройки. |

Кодер: `h264_crf14` для архива, `h264_crf17` для итогового файла.

#### Шумодав теней SOTA (`shadow_denoise_sota`)

BM3D в 32-битной плавающей точке чистит весь кадр, а плавная маска яркости оставляет очищенную яркость только в тенях: средние тона и света остаются как были. Цветовые плоскости чистятся везде: цветовой шум уродлив при любой яркости. Поверх очищенных теней возвращается микрозерно, чтобы они не выглядели пластиковыми. Для ночной цифровой съёмки и съёмки при слабом свете, где шум сидит в тёмном. BM3D работает на видеокарте или на процессоре — как скажет блок ОБРАБОТКА (раздел «BM3D на видеокарте»).

| Поле | Значения | Что меняет |
|---|---|---|
| `sigma` Сигма BM3D | `1.0` … `4.0`; по умолчанию `2.5` | Сила BM3D по яркости; цвет получает 0,6 от неё. |
| `noise` Шум | `auto`, `fixed`; по умолчанию `auto` | Авто поднимает сигму по измеренному шуму, у яркости и цвета — по своему. |
| `grain_back` Возврат зерна | `0.0` … `2.0`; по умолчанию `0.6` | Микрозерно поверх очищенных теней; `0` — без него. |
| `shadow_threshold` Порог теней | `0.0` … `0.5`; по умолчанию `0.2` | Яркость (от 0 до 1), на которой кончаются тени: выше — чистится больше картинки. |
| `transition` Переход маски | `0.01` … `0.4`; по умолчанию `0.1` | Ширина плавного перехода от очищенного к нетронутому: ниже порога минус переход — полная чистка, от порога и выше — никакой. |
| `preview_mask` Показать маску | вкл., выкл.; по умолчанию выкл. | Результат — сама маска теней, белая там, где чистит: для подбора порога. |

Кодер: `h264_crf17` или `prores_lt`.

#### Чистка цветового шума (`chroma_cleanup`)

DFTTest только по двум цветовым плоскостям. Яркость не трогается, поэтому деталь остаётся как была. Цвет выдерживает сигму сильнее, чем яркость, без видимой потери: он хранится в меньшем разрешении. Для цветных пятен и грязного синего канала: старые компактные камеры, AVCHD с низким потоком.

| Поле | Значения | Что меняет |
|---|---|---|
| `strength` Сила | `light`, `medium`, `strong`; по умолчанию `medium` | Сигма по цвету: 6, 12 или 20. |
| `noise` Шум | `auto`, `fixed`; по умолчанию `auto` | Авто поднимает сигму по измеренному цветовому шуму — большему из U и V. |

Кодер: `h264_crf17`.

### Дебанд

#### Мягкий дебанд (`deband_safe`)

neo_f3kdb с лёгкими настройками в 16 битах, без зерна: ступеньки на небе, стенах и в ночном свете уходят, края остаются резкими.

| Поле | Значения | Что меняет |
|---|---|---|
| `range` Радиус дебанда | `8` … `32`; по умолчанию `12` | Как далеко neo_f3kdb ищет соседей для сглаживания: больше — сильнее, уходят более широкие полосы. |
| `y` Порог Y | `0` … `128`; по умолчанию `48` | Какой перепад яркости ещё сглаживается. |
| `cb`, `cr` Порог Cb и Cr | `0` … `128`; по умолчанию `32` | То же для двух цветовых плоскостей. |

Кодер: `h264_crf17` или `h265_crf17`. Оба пишут 10 бит, поэтому сглаженные градиенты не расслаиваются снова.

#### Дебанд с тонким зерном (`deband_fine_grain`)

Тот же neo_f3kdb, затем AddGrain кладёт тонкое зерно поверх сглаженных градиентов. Картинка сохраняет живую фактуру вместо слишком чистого вида дешёвого сжатия.

| Поле | Значения | Что меняет |
|---|---|---|
| `range` Радиус дебанда | `8` … `32`; по умолчанию `14` | Как далеко neo_f3kdb ищет соседей для сглаживания: больше — сильнее. |
| `y` Порог Y | `0` … `128`; по умолчанию `48` | Какой перепад яркости ещё сглаживается. |
| `cb`, `cr` Порог Cb и Cr | `0` … `128`; по умолчанию `32` | То же для двух цветовых плоскостей. |
| `grain_var` Дисперсия зерна | `0.0` … `2.0`; по умолчанию `0.6` | Дисперсия AddGrain по яркости; цвет получает 0,27 от неё. |

Кодер: `prores_lt` для грейдинга.

### Мастер

#### Плёночная пересборка (`filmic_rebuild`)

Три ступени за один прогон: BM3D убирает цифровой шум, neo_f3kdb — полосы, затем зерно кладётся по яркости — больше всего в тенях, как на настоящей плёнке, меньше в средних тонах, меньше всего в светах. Зоны переходят друг в друга на 0,1 яркости. Один пресет для плёночного материала. BM3D работает там, где скажет блок ОБРАБОТКА.

| Поле | Значения | Что меняет |
|---|---|---|
| `sigma` Сигма BM3D | `1.0` … `3.5`; по умолчанию `2.0` | Сила BM3D по яркости; цвет получает 0,6 от неё. |
| `noise` Шум | `auto`, `fixed`; по умолчанию `auto` | Авто поднимает сигму по измеренному шуму. |
| `deband_range` Радиус дебанда | `8` … `32`; по умолчанию `14` | Как далеко neo_f3kdb ищет соседей для сглаживания. |
| `grain_shadow` Зерно в тенях | `0.0` … `3.0`; по умолчанию `1.5` | Дисперсия зерна там, где картинка темнее порога теней. |
| `grain_mid` Зерно в средних | `0.0` … `3.0`; по умолчанию `0.9` | Дисперсия зерна между двумя порогами. |
| `grain_high` Зерно в светах | `0.0` … `3.0`; по умолчанию `0.4` | Дисперсия зерна там, где картинка светлее порога светов. |
| `shadow_threshold` Порог теней | `0.0` … `0.5`; по умолчанию `0.3` | Яркость (от 0 до 1), на которой кончаются тени. |
| `high_threshold` Порог светов | `0.5` … `1.0`; по умолчанию `0.65` | Яркость (от 0 до 1), с которой начинаются света. |

Кодер: `prores_lt` или `h265_crf17`.

#### Чистый архив (`archive_clean`)

Лёгкий DFTTest и лёгкий neo_f3kdb без зерна: шум и полосы уходят, фактура не добавляется. Нейтральный плоский мастер для долгого хранения, сдачи или чистого промежуточного файла. Грейдинг лучше идёт по материалу с зерном: если он впереди, берите `pregrade_prep` или `filmic_rebuild`.

| Поле | Значения | Что меняет |
|---|---|---|
| `denoise` Шумодав | `light`, `medium`, `strong`; по умолчанию `light` | Сигма DFTTest 4, 8 или 14. |
| `noise` Шум | `auto`, `fixed`; по умолчанию `auto` | Авто поднимает сигму по измеренному шуму. |
| `range` Радиус дебанда | `8` … `32`; по умолчанию `10` | Как далеко neo_f3kdb ищет соседей для сглаживания. |

Кодер: `prores_422hq` или `prores_422hq_mxf`. Встроенный профиль `archival_master` пишет `prores_422hq`.

#### Подготовка к грейдингу (`pregrade_prep`)

Очень лёгкий DFTTest и больше ничего: ни дебанда, ни зерна. Материал уходит в Resolve или Premiere почти таким, каким был, только без самого острого шума, и колорист не работает поверх него. Дебанда здесь нет намеренно: он может спорить с цветовыми инструментами; если он нужен — после грейдинга.

| Поле | Значения | Что меняет |
|---|---|---|
| `strength` Сила | `light`, `medium`; по умолчанию `light` | Сигма DFTTest 3 или 6. |
| `noise` Шум | `auto`, `fixed`; по умолчанию `auto` | Авто поднимает сигму по измеренному шуму. |

Кодер: `prores_422hq` (встроенный профиль `resolve_handoff`) или `prores_lt_mxf` для Premiere и Avid.

## ПЛЁНКА

Образы киноплёнок. Каждый образ собран из одних и тех же частей: смягчение MTF, ореол светов, зерно, кривая гаммы, приподнятый чёрный, обесцвечивание. `intensity` меняет силу всего образа и стоит на каждой странице палитры.

| Поле | Значения | Что меняет |
|---|---|---|
| `intensity` Интенсивность | `0.0` … `2.0`; по умолчанию `1.0` | Сила всего образа: `0` — выключен, `1` — как настроен, `2` — сильно. |

### Плёнка

#### Плёнка 35 мм (`film_35mm`)

Kodak 35 мм с выбором плёнки. Плёнки различаются зерном, контрастом, ореолом и оттенком: 250D — дневная, нейтральная, мелкое зерно; 500T — для ламп накаливания, светочувствительнее, зерно умеренное, оттенок холоднее; 50D — дневная, самое чистое зерно.

| Поле | Значения | Что меняет |
|---|---|---|
| `stock` Плёнка | `250D`, `500T`, `50D`; по умолчанию `250D` | Плёнка, как описано выше. |
| `intensity` Интенсивность | `0.0` … `2.0`; по умолчанию `1.0` | Сила всего образа. |

Кодер: `prores_lt` или `prores_lt_mxf`. Встроенный профиль `filmic_warm_35mm` — 250D при `intensity` 1,0 в `h264_crf14`.

#### Плёнка 16 мм (`film_16mm`)

Живое ощущение 16 мм: мягче 35 мм — меньший кадр разрешает меньше; зерно заметнее; ореол сильнее; чёрный приподнят. Для документального или независимого кино на цифровом материале. Одно поле — `intensity`.

Кодер: `prores_lt`.

#### Super 8 (`super8`)

Самая крайняя из плёнок: самое крупное зерно, самая мягкая оптика, самый сильный ореол, приподнятый чёрный, сниженный контраст — домашнее кино 1970-х. Для клипов и стилизованных вставок. Одно поле — `intensity`.

Кодер: `h264_crf17`: зерно — часть образа, и итоговый файл со сжатием его сохраняет.

#### IMAX 70 мм (`imax_70mm`)

Большой формат 65/70 мм, противоположность Super 8: разрешение сохраняется, зерна почти нет (на большом кадре каждое зерно крошечное рядом с картинкой), мягкий ореол трогает только самые яркие света, а едва заметное дрожание кадра снимает слишком чистый цифровой вид. Для кадров, которые должны ощущаться эпично, а не плёночно.

| Поле | Значения | Что меняет |
|---|---|---|
| `intensity` Интенсивность | `0.0` … `2.0`; по умолчанию `1.0` | Сила всего образа. |
| `gate_weave` Дрожание кадра | вкл., выкл.; по умолчанию вкл. | Каждый кадр немного сдвигается, как плёнка в кадровом окне проектора: на 0 или 2 пикселя в каждую сторону — цвету 4:2:0 нужны чётные шаги. Один файл дрожит одинаково при каждом прогоне. Выключено или `intensity` 0 — картинка стоит. |

Кодер: `prores_lt` или `h265_crf17`.

### Образ

#### Кинематографичный (`cinematic`)

Универсальный мягкий плёночный образ, не привязанный к конкретной плёнке: лёгкое смягчение MTF, лёгкое свечение светов, тонкое зерно. Ни крупного зерна, ни дрожания кадра, ни мерцания. Безопасный первый образ для любого современного цифрового материала. Одно поле — `intensity`: оно меняет зерно, ореол и смягчение вместе.

Кодер: `prores_lt` или `h264_crf17`.

#### Отбеливание (`bleach_bypass`)

Вид копии, из которой не вымыли серебро: поверх цветного изображения лежит чёрно-белое. Высокий контраст, серебристые серые, яркие света, мало цвета. Сильное стилистическое решение. Одно поле — `intensity`: выше — больше контраста, меньше цвета и чуть больше мягкости.

Кодер: `prores_lt`.

#### Анаморфот (`anamorphic_scope`)

Образ синемаскопа с анаморфотной оптикой: длинные горизонтальные синие блики только от ярких светов и холодные бирюзовые тени. Работа идёт в 16-битном RGB, поэтому блики не обрезаются: маска светов, горизонтальное размытие на длину блика, синий оттенок и сложение с картинкой — блик только добавляет свет. Затем бирюзовый сдвиг в тенях (яркость ниже 0,4) и лёгкое зерно. Кадр не обрезается до 2,39:1: настоящий кадр синемаскопа кадрируют при монтаже.

| Поле | Значения | Что меняет |
|---|---|---|
| `intensity` Интенсивность | `0.0` … `2.0`; по умолчанию `1.0` | Сила всего образа, вместе с бликами и бирюзой. |
| `flare_len` Длина блика | `32` … `256`; по умолчанию `96` | Длина полосы блика в пикселях: около 48 — сдержанно, 160 — драматично, 256 — предельно. |
| `flare_thr` Порог блика | `0.0` … `1.0`; по умолчанию `0.78` | С какой яркости свет даёт блик: 0,85 — только самые яркие, 0,70 — бликует большая часть картинки. |
| `teal_shadow` Бирюза в тенях | `0.0` … `1.0`; по умолчанию `0.35` | Сила бирюзового оттенка в тенях: `0` — без него, 0,6 — сильно. |

Кодер: `prores_lt` для колориста, `h265_crf14` для итогового файла.

## РЕТРО

Аналоговый характер видео и фото. У каждого пресета есть `intensity`, как в палитре ПЛЁНКА: `0.0` … `2.0`, по умолчанию `1.0`.

### Видео

#### VHS и кинескоп (`vhs_crt`)

Композитный сигнал, кассета VHS, кинескопный телевизор: сильное растекание цвета вбок (главная примета образа), мягкая оптика, лёгкое расхождение цвета, слабый шум. Одно поле — `intensity`. Встроенный профиль `vhs_dreamy` запускает его с 1,2.

Кодер: `h264_crf17`.

#### Камкордер 90-х (`camcorder_90s`)

Бытовой камкордер 90-х: мягче VHS, слегка пересвечен, лёгкое растекание цвета и шум плёнки — не сломанный сигнал, а домашнее видео. Одно поле — `intensity`.

Кодер: `h264_crf17`.

### Фото

#### Полароид (`polaroid`)

Моментальное фото Polaroid SX-70 70-х и 80-х: мягкая оптика, карамельное свечение светов (даже светлая кожа чуть светится), чёрный, который никогда не доходит до чёрного, тёплые кремовые полутона, чуть меньше цвета, тёмные углы. Мягче и менее зернисто, чем Super 8.

| Поле | Значения | Что меняет |
|---|---|---|
| `intensity` Интенсивность | `0.0` … `2.0`; по умолчанию `1.0` | Сила всего образа, вместе с виньеткой. |
| `vignette` Виньетка | `0.0` … `1.0`; по умолчанию `0.55` | Насколько темнеют углы: `0` — без виньетки, `1` — углы уходят в чёрный. |

Кодер: `h264_crf17`.

## РЕСТАВРАЦИЯ

То, что монтажные программы делают грубо или не делают вовсе: деинтерлейс, обратный телесин, шумодав вдоль движения, артефакты сжатия, увеличение, новые кадры. Четыре пресета палитры работают на нейросетях (MLRT).

### Чересстрочность

#### Деинтерлейс QTGMC (`qtgmc_deinterlace`)

QTGMC из havsfunc: каждое поле увеличивается через NNEDI3 и сглаживается во времени вдоль движения, найденного MVTools. Получаются прогрессивные кадры без «гребёнки», мерцания и двоения на быстрых панорамах. Для DV, HDV, оцифровки VHS, S-VHS и U-matic, эфирного TS. Пресет не давит шум: шумодав — следующим шагом.

| Поле | Значения | Что меняет |
|---|---|---|
| `field_order` Порядок полей | `tff`, `bff`; по умолчанию `tff` | TFF — первым верхнее поле (эфир, HDV, DV NTSC); BFF — первым нижнее (DV PAL). При неверном порядке движение дёргается вперёд-назад. |
| `preset` Пресет QTGMC | 11 ступеней от `Draft` до `Placebo`; по умолчанию `Medium` | Скорость против качества: Draft — самый быстрый, Placebo — самый медленный. |
| `output_fps` Частота на выходе | `single`, `double`; по умолчанию `single` | Одинарная — частота исходника. Двойная — каждое поле становится кадром: вдвое больше кадров (из 25i в 50p), самое плавное движение, вдвое больше работы кодеру. |

Кодер: `prores_lt` для дальнейшей работы, `h264_crf17` для итогового мастера.

#### Обратный телесин TIVTC (`tivtc_ivtc`)

Обратный телесин: TFM собирает плёночные поля обратно в кадры, TDecimate выбрасывает повторный кадр каждого цикла. NTSC 29,97 к/с с раскладкой 3:2 возвращается в прогрессивный плёночный мастер 23,976 к/с. Для NTSC DVD, эфирных копий, оцифрованной плёнки. Кадров становится меньше на `rdrop` из каждых `cycle` — при значениях по умолчанию на пятую часть; длина ролика не меняется. Исходник ниже 29 к/с не принимается: он уже идёт с частотой плёнки, и прореживание выбросило бы каждый пятый настоящий кадр.

| Поле | Значения | Что меняет |
|---|---|---|
| `pp` Постобработка TFM | `0` … `7`; по умолчанию `6` | `0` — выключена … `7` — деинтерлейс всего, что не совпало; `6` деинтерлейсит кадры, которые TFM не смог чисто сопоставить. |
| `cycle` Цикл | `2` … `25`; по умолчанию `5` | Цикл TDecimate в кадрах; 5 для обычного телесина NTSC. |
| `rdrop` Выброс за цикл | `1` … `5`; по умолчанию `1` | Сколько кадров выбрасывается из цикла; 1 из 5 для NTSC. |

Кодер: `prores_422` или `prores_422hq_mxf`.

### Шум

#### MVTools MCDegrain (`mvtools_mcdegrain`)

MVTools отслеживает каждый блок в кадрах до и после, а MDegrain усредняет каждый пиксель с соседями вдоль движения. Шум уходит; неподвижная фактура остаётся резкой, движущаяся тоже — она усредняется вдоль своего движения, а не поперёк. Для съёмки на высоком ISO и при слабом свете, где кожа и ткань должны сохранить фактуру.

| Поле | Значения | Что меняет |
|---|---|---|
| `radius` Радиус | `1` … `3`; по умолчанию `2` | Сколько кадров до и после берётся: 2 — окно из 5 кадров; больше — сильнее и медленнее. |
| `thsad` THSAD | `100` … `400`; по умолчанию `200` | Порог различия блока: ниже — усредняются только уверенные совпадения, выше — усреднения больше. |
| `noise` Шум | `auto`, `fixed`; по умолчанию `auto` | Авто поднимает `thsad` и порог смены сцены по измеренному шуму яркости. |
| `blksize` Размер блока | `8`, `16`; по умолчанию `16` | Блок поиска движения: 16 для SD и HD, быстрее; 8 для мелкой детали и 4K, медленнее. |

Кодер: `prores_lt` или `h265_crf17`.

#### Шумодав DPIR (`dpir_denoise`)

Нейросетевой пресет: ему нужен MLRT. DPIR, глубокая сеть-шумодав, сохраняет фактуру кожи и ткани на очень грязном материале, где BM3D и DFTTest её замыливают: ISO 6400 и выше, телефон в темноте. Сети говорят, насколько сильный шум (`strength`). Размер кадра и число кадров не меняются.

| Поле | Значения | Что меняет |
|---|---|---|
| `strength` Сила | `1.0` … `50.0`; по умолчанию `10.0` | Уровень шума, на который рассчитана сеть: 5 — лёгкий дробовой шум, 10 — средний (ISO 1600–3200), 15 — сильный (ISO 6400 и выше), 25 — очень сильный (ISO 12800, телефон в темноте), 50 — предельный. |
| `model` Модель | `drunet_color` Цвет (по умолчанию), `drunet_gray` Серый, `drunet_deblocking_color` Блоки, цвет, `drunet_deblocking_gray` Блоки, серый | Цвет — цветное видео; Блоки — ещё и блоки JPEG и MPEG; Серый — только яркость, цвет остаётся как есть (чёрно-белый материал). |
| `tile` Плитка | `256` … `512`, шаг 16; по умолчанию `384` | Кусок кадра, который сеть берёт за раз, в пикселях: меньше — меньше видеопамяти, медленнее. |

Кодер: `prores_lt` для колориста, `h264_crf14` для итогового файла.

### Артефакты

#### Блоки H.264 (`deblock_h264_artefacts`)

Deblock_QED из havsfunc — против артефактов блочного сжатия: границ блоков 8×8, ореолов вокруг краёв, москитного шума. Он сначала находит настоящие края и сглаживает только границы блоков, так что настоящая деталь остаётся. Для старых копий из сети, пересжатий мессенджеров (WhatsApp, Telegram), слабого эфира SD.

| Поле | Значения | Что меняет |
|---|---|---|
| `quant1` Квант 1 | `16` … `32`; по умолчанию `24` | Сила на краях блоков: выше — сильнее. |
| `quant2` Квант 2 | `16` … `32`; по умолчанию `26` | Сила внутри блоков. |
| `aoffset` Офсет альфа | `0` … `2`; по умолчанию `1` | Чувствительность фильтра к краям. |
| `boffset` Офсет бета | `0` … `2`; по умолчанию `1` | Чувствительность фильтра внутри блоков. |

Кодер: `h264_crf17`.

#### Радуга и перекрёстные помехи (`derainbow_decross`)

Радуга, бегущие точки и перекрёстные цветовые помехи композита NTSC — мелкое цветовое мерцание, которое перемещается от кадра к кадру. Движение ищется по яркости, а цветовые плоскости усредняются вдоль него по 3 кадрам — текущему, предыдущему и следующему. Бегущие помехи гасят друг друга, настоящий цвет остаётся. Яркость не трогается, поэтому резкость сохраняется. Для оцифрованных VHS, U-matic, BetaSP, эфирных мастеров, S-Video через SDI.

| Поле | Значения | Что меняет |
|---|---|---|
| `strength` Сила | `0.0` … `1.0`; по умолчанию `0.6` | Насколько сглаживается цвет: `0` — как было, `1` — полностью. |
| `blksize` Размер блока | `8`, `16`; по умолчанию `16` | Блок поиска движения: 16 для SD и HD, 8 для мелкой детали и 4K. |

Кодер: `prores_lt` или `h264_crf17`.

#### Дымка и локальный контраст (`dehaze_local_contrast`)

Локальный контраст только по яркости: разница между картинкой и её размытой копией добавляется обратно с весом маски яркости — наибольшим в средних тонах и сходящим на нет к чёрному и белому. Света не выгорают, тени не становятся грязными. Цвет не трогается, поэтому не сдвигается; счёт в 16 битах, без ореолов. Для дымки и плоской неконтрастной картинки.

| Поле | Значения | Что меняет |
|---|---|---|
| `strength` Сила | `0.0` … `2.0`; по умолчанию `1.0` | Сколько локального контраста добавляется: `0` — картинка как была, `2` — сильно. |
| `radius` Радиус | `1` … `16`; по умолчанию `8` | Размер размытия в пикселях: около 8 — ясность мелкой структуры, 12–16 — дымка на крупных формах. |

Кодер: `prores_lt` для колориста, `h264_crf17` для итогового файла.

### Масштаб

#### Увеличение NNEDI3 2X (`nnedi3_upscale_2x`)

NNEDI3 (znedi3 через `nnedi3_resample`) удваивает ширину и высоту: чистые края, одинаковый результат при каждом прогоне, никакая сеть не выдумывает фактуру, MLRT не нужен. Для архива SD и HD, который нужно увеличить предсказуемо. Из 1920×1080 получается 3840×2160.

| Поле | Значения | Что меняет |
|---|---|---|
| `quality` Качество | `fast`, `balanced`, `best`; по умолчанию `balanced` | Быстро — облегчённый NNEDI3; сбалансировано — как настроено; лучшее — медленнее, чище края. |
| `chroma` Увеличение цвета | `spline36`, `nnedi3`; по умолчанию `spline36` | Spline36 надёжнее; NNEDI3 резче и медленнее. |

Кодер: `prores_lt` для передачи дальше, `h264_crf14` или `h265_crf14` для итогового файла.

#### Real-ESRGAN 2x (`vsmlrt_realesrgan_2x`)

Нейросетевой пресет: ему нужен MLRT. Real-ESRGAN удваивает ширину и высоту (из 1080p в 3840×2160) с более чистыми и чёткими линиями, чем Lanczos или Spline36. Его модели в vs-mlrt сделаны для рисованной анимации: живое видео они могут пережать по резкости и сгладить фактуру — для живого видео надёжнее `nnedi3_upscale_2x` (без MLRT).

| Поле | Значения | Что меняет |
|---|---|---|
| `model` Модель | `animevideov3` Аниме (по умолчанию), `animejanaiV2-L1` … `animejanaiV2-L3` AnimeJaNai 1–3 | Аниме — самая лёгкая, AnimeJaNai 1–3 — от лёгкой к сильной; все — для рисованной анимации. |
| `tile` Плитка | `256` … `768`, шаг 16; по умолчанию `384` | Кусок кадра, который сеть берёт за раз, в пикселях: меньше — меньше видеопамяти, медленнее. |
| `tile_pad` Перекрытие плиток | `4` … `64`; по умолчанию `16` | На сколько пикселей куски заходят друг на друга, чтобы не было видно швов. |

Общих моделей Real-ESRGAN (`general-x4v3`, `general-wdn-x4v3`) в vs-mlrt нет: пресет их не предлагает, а модель, которой нет в установленном vs-mlrt, отклоняется по имени и никогда не подменяется другой.

Кодер: `prores_lt` для дальнейшей работы, `h265_crf14` для итогового файла.

#### Пересборка мягкого HD 2x (`soft_hd_rebuild_2x`)

Нейросетевой пресет: ему нужен MLRT. Для материала, который по размеру HD, а детали в нём гораздо меньше: мягкая оптика, объединение пикселей матрицы, сильный фильтр сглаживания, старые кодеки, поколения архивных копий. Сначала лёгкая чистка DFTTest, чтобы сеть не увеличивала шум и блоки; затем Real-ESRGAN вдвое по ширине и высоте; затем бережное повышение резкости яркости.

| Поле | Значения | Что меняет |
|---|---|---|
| `rebuild` Пересборка | `conservative` Бережно, `balanced` Сбалансированно (по умолчанию), `aggressive` Сильно | Сколько детали возвращается после сети: Бережно — без ореолов, Сильно — для очень мягких исходников. |
| `cleanup` Чистка | `light`, `medium`, `strong`; по умолчанию `medium` | Чистка DFTTest перед сетью: сигма 2, 4 или 7. |
| `model`, `tile`, `tile_pad` | как у Real-ESRGAN 2x | Модель, плитка и её перекрытие. |

Кодер: `prores_lt` для грейдинга, `h265_crf14` для итогового файла.

## Сила шумодава по измеренному шуму

Семь шумодавов — `mild_denoise`, `chroma_cleanup`, `archive_clean`, `pregrade_prep`, `shadow_denoise_sota`, `filmic_rebuild`, `mvtools_mcdegrain` — перед работой меряют шум исходника (`noise=auto`, по умолчанию):

- 5 кадров из разных мест ролика, только ровные участки: текстура, края и участки ближе 3 % к чёрному или белому не считаются;
- итог — стандартное отклонение в 8-битных кодах, у яркости и цвета своё.

Их настройки (`strength`, `sigma`, `thsad`) сделаны под шум около 2 кодов. Шум сильнее поднимает их: сигма BM3D и пороги MVTools растут вместе с шумом, сигма DFTTest — с его квадратом. Ниже настройки сила не опускается, так что чистый материал получает ровно то, что задано. Вместе с шумом растёт и порог смены сцены у MVTools: на сильном шуме каждый блок вышел бы за порог по умолчанию, весь кадр считался бы новой сценой и не чистился.

`noise=fixed` (`--set noise=fixed`) берёт настройки как есть. Что измерено и что пресет из этого сделал — в отчёте прогона (поле `noise` у каждого файла), например:

```text
[NOISE] mild_denoise: noise 5.34 / 3.44 / 2.75 (8-bit, Y/U/V) -> DFTTest sigma 57.1
```

## BM3D на видеокарте

`shadow_denoise_sota` и `filmic_rebuild` — это в основном BM3D. `bm3dvk` считает BM3D на устройстве Vulkan ядра VapourSynth — NVIDIA, AMD или Intel, с обычным драйвером видеокарты; CUDA Toolkit не нужен. Без устройства Vulkan BM3D считается на процессоре (`bm3d`).

Блок ОБРАБОТКА (`vs_accel`) у этих двух пресетов:

| Значение | Где работает BM3D |
|---|---|
| `auto` (по умолчанию) | На видеокарте, когда VapourSynth видит рабочее устройство Vulkan, иначе на процессоре. |
| `cpu` | На процессоре: `bm3d` (или `bm3dcpu`, где он загружается). |
| `gpu` | На видеокарте через Vulkan (`bm3dvk`), любого производителя; на процессоре, когда устройства Vulkan нет. |

- На видеокарте два прогона одного файла сходятся примерно на 65 дБ PSNR: видеокарта складывает в разном порядке. `bm3d` на процессоре даёт те же кадры байт в байт при каждом прогоне.
- Остальные фильтры работают на процессоре, и видеокарта им не помогает; поэтому ОБРАБОТКА показана только там, где она что-то меняет: у двух пресетов BM3D, у нейросетевых пресетов и у профилей.
- СЕРВИС → «BM3D: видеокарта или процессор» (`bench_gpu`) меряет кадры в секунду у каждого на первом видео Источника; «Доктор» делает живой вызов и называет устройство. При голом запуске `.vpy` через `vspipe` одно из двух называет `AUDION_VS_BM3D=vulkan` или `AUDION_VS_BM3D=bm3d`.

## Нейросетевые пресеты и MLRT

Три пресета работают на vs-mlrt — нейросетях внутри VapourSynth: `dpir_denoise`, `vsmlrt_realesrgan_2x`, `soft_hd_rebuild_2x`. Интерполяции RIFE нет: на RTX 5070 TensorRT строит неверные промежуточные кадры, DirectML доступен только через ONNX Runtime старого интерфейса плагинов, который VapourSynth R80+ не загружает, а на процессоре новый кадр 4K считается 1,28 с — около получаса на минуту 24p, удвоенную до 48p ([Решения](../DECISIONS_RU.md#интерполяции-кадров-нет)).

- **Установка.** Программа ищет видеокарту NVIDIA RTX через `nvidia-smi`. Если она есть, MLRT (`install_mlrt`) предлагается среди дополнительных компонентов при запуске и в SETUP: TensorRT, ONNX Runtime и модели, около 3,5 ГБ загрузки, под эту видеокарту. MLRT ставится в папку движка, в Windows ничего не пишется. Пока он не установлен, страница нейросетевого пресета показывает «MLRT НЕ УСТАНОВЛЕН».
- **Без видеокарты RTX и без MLRT** окно этих пресетов не показывает, а консоль отказывает до начала строкой `[PREFLIGHT] FAIL MLRT` (код выхода 2). MLRT, поставленный на машине с RTX, работает и после переноса папки на другую машину: там сети идут на DirectML или на процессоре.
- **Где работает сеть** — блок ОБРАБОТКА (`vs_accel`):

| Значение | Где работает сеть |
|---|---|
| `auto` (по умолчанию) | TensorRT на видеокарте NVIDIA RTX, иначе DirectML на видеокарте, иначе процессор. Без видеокарты RTX TensorRT даже не пробуется. |
| `cpu` | ONNX Runtime на процессоре: работает везде и во много раз медленнее. |
| `gpu` | TensorRT на NVIDIA RTX, DirectML на другой видеокарте. |

- **Первый прогон модели** собирает её движок TensorRT: 30–120 с. Движок хранится на диске, следующие прогоны начинаются сразу. Другой размер плитки или другой размер кадра собирает новый движок.
- **Плитка** — кусок кадра, который сеть берёт за раз. Меньшей плитке нужно меньше видеопамяти, и работает она медленнее: если видеопамяти не хватает, уменьшите `tile`. `tile_pad` заводит куски друг на друга, чтобы не было видно швов.
- **Размер и кадры.** `vsmlrt_realesrgan_2x` и `soft_hd_rebuild_2x` удваивают ширину и высоту. `dpir_denoise` сохраняет и то и другое.

```cmd
vs_cli.cmd run --operation vsmlrt_realesrgan_2x --set model=animejanaiV2-L2 --set vs_accel=gpu --encoder prores_lt
```

## Выбор кодера

Лестница качества одна для программных кодеров, NVENC, QuickSync и AMF: **14 → 17 → 21**, три ступени, которые ясно различаются. По умолчанию окно пишет x.264 на процессоре с качеством 14 в MP4, то есть `h264_crf14`.

| Кодер | Когда |
|---|---|
| `h264_crf14` / `h265_crf14` | Почти без потерь: архив, мастер для дальнейшей работы. |
| `h264_crf17` / `h265_crf17` | Потери почти незаметны: итоговый мастер. |
| `h264_crf21` / `h265_crf21` | Веб, прокси, просмотр. |
| `prores_lt` | ProRes LT, 10 бит 4:2:2 в MOV: грейдинг и обмен с монтажом, без кеинга. ProRes окна по умолчанию. |
| `prores_lt_mxf` | ProRes LT в MXF: обмен с Premiere и Avid. |
| `prores_422` / `prores_422_mxf` | Чуть больше потока, чем у LT; MXF — для Premiere и Avid. |
| `prores_422hq` / `prores_422hq_mxf` | Кеинг и повторные проходы; HQ в MXF — для эфира и чистовой сборки в Avid. |
| `dnxhr_lb` / `_sq` / `_hq` / `_hqx` | DNxHR: LB — низкий поток, SQ — стандарт, HQ — высокое качество, все 8 бит 4:2:2; HQX — 10 бит. |
| `h264_nvenc_q14` / `_q17` / `_q21` | Аппаратный H.264 NVIDIA, 8 бит 4:2:0. CQ вместо CRF. Кодирование уходит с процессора, и фильтры VapourSynth его не ждут. |
| `h265_nvenc_q14` / `_q17` / `_q21` | Аппаратный HEVC NVIDIA, 10 бит. Фильтры на процессоре или видеокарте, кодирование на NVENC: процессор не простаивает. |
| `h264_qsv_q14` / `_q17` / `_q21` | Intel QuickSync H.264: пакеты и прокси на графике Intel. |
| `h265_qsv_q14` / `_q17` / `_q21` | Intel QuickSync HEVC, 10 бит, где графика это умеет. |
| `h264_amf_q14` / `_q17` / `_q21` | AMD AMF H.264 через CQP. |
| `h265_amf_q14` / `_q17` / `_q21` | AMD AMF HEVC, 10 бит. |

x.264 и x.265 на процессоре пишут 10 бит 4:2:0, в MP4 или MKV. Аппаратный кодер, не прошедший проверку на этой машине (СЕРВИС → «Возможности оборудования»), в окне выключен.

**Правило.** Для любого шага, кроме последнего, — `prores_lt` или `prores_lt_mxf`, либо DNxHR, если его предпочитает принимающая программа. Для итогового файла — `h264_crf14` или `h264_crf17` (программный кодер, лучшее качество на бит) либо аппаратная лестница машины (`nvenc`, `qsv`, `amf`), когда важно время.

### Аппаратный или программный

| Задача | Кодер |
|---|---|
| Тяжёлая обработка (`filmic_rebuild`, `mvtools_mcdegrain`) на NVIDIA | **NVENC**: процессор свободен для фильтров, весь прогон короче на 30–50 %. |
| Итоговый файл, где важнее всего качество на бит | **libx264 / libx265 CRF**: программный кодер всё ещё чуть экономнее на низких CRF. |
| Графика Intel, пакет на ноутбуке | **QuickSync**: хорошая скорость при малой нагрузке на процессор. |
| AMD Radeon | **AMF**: та же лестница 14 / 17 / 21, без кодирования на процессоре. |
| Пакет из сотен файлов | **NVENC, QuickSync или AMF**: сэкономленное время складывается. |
| Рабочего аппаратного кодера нет | Только программный: `h264_crf*`, `h265_crf*`. |

NVENC на видеокартах RTX 40 и RTX 50 даёт качество, сравнимое с libx264 medium при том же CQ. На старых картах (GTX 10, RTX 20) программный CRF чуть экономнее при том же качестве, а NVENC всё равно во много раз быстрее.

## Звук

Через пресет идёт только видео; звук обрабатывается сам:

- звук исходника копируется как есть;
- звук, который MP4 не принимает как есть, — например PCM исходника ProRes, идущего в x.264 или x.265, — кодируется в AAC 384 кбит/с;
- в MXF звук идёт PCM 24 бит 48 кГц: другого его упаковщик не пишет.

Готовый файл получает цветовой диапазон исходника (`-color_range`): полнодиапазонный исходник остаётся полным.
